# Secrets

Every secret the platform needs, where it comes from and where it ends up. **Infisical is the source of truth** for
our own secrets (project path `/experiments/voice_ai_agent`, see `.infisical.yaml`). The services on AWS read them
from AWS Secrets Manager, so each one below lists the Secrets Manager name it must reach.

Fill these in once the platform is built. Nothing is deployed until then.

## How they get to AWS

Our secrets sit in Infisical and are copied into Secrets Manager, ideally by an Infisical secret sync to AWS Secrets
Manager (one JSON secret per group below). `platform-core.yaml` currently creates the `cloudflared-token` and
`agent-shared` secrets itself with placeholder values. When the sync is set up, either let it overwrite those
values, or change the template to take the secret ARNs as parameters so the sync owns them. Decide when wiring it.

**Tenant secrets are different:** a business's WhatsApp token and Yoco key come from the business through the app
(Embedded Signup, Yoco connect) and provisioning writes them straight to Secrets Manager. They never go into
Infisical.

## Our secrets (Infisical → Secrets Manager)

Names assume the platform stack is called `voice-platform`.

### `voice-platform/cloudflared-token` (plain string)

| Secret | Needed by | How to get it |
|---|---|---|
| Cloudflare tunnel token | `cloudflared` service (platform-core) | Cloudflare Zero Trust → Networks → Tunnels → create a tunnel for the platform → copy the token from the install command. Public hostnames: `app.<domain>` → `http://app.platform.internal:3000`, `api.<domain>` → `http://api.platform.internal:8000`, later `calls.<domain>` → the router |

### `voice-platform/agent-shared` (JSON; every key must exist, empty is fine)

| Key | Needed by | How to get it |
|---|---|---|
| `DEEPGRAM_API_KEY` | every tenant agent (speech to text, Aura voices) | Deepgram console → API keys. A key with usage scope lets us report minutes per tenant |
| `VOXCPM_URL` | tenant agents using a custom VoxCPM voice | URL of the Modal app after `modal deploy services/tts/modal_app.py` |
| `VOXCPM_TOKEN` | same | The token the Modal app checks (set when deploying it) |

### `voice-platform/router` (JSON) — added with the router (milestone 2)

| Key | Needed by | How to get it |
|---|---|---|
| `WHATSAPP_APP_SECRET` | router (checks Meta's webhook signatures) | Meta developer app → App settings → Basic → App secret |
| `WHATSAPP_WEBHOOK_VERIFY_TOKEN` | router (Meta's webhook handshake) | Any random string; enter the same value in the app's WhatsApp webhook settings |
| `META_APP_ID` | Embedded Signup (app and API) | Meta developer app → App settings → Basic |
| `META_EMBEDDED_SIGNUP_CONFIG_ID` | Embedded Signup | Meta app → Facebook Login for Business → Configurations (after Tech Provider approval) |

### `voice-platform/test-whatsapp` (JSON) — our internal test number, used by every tenant's staging

| Key | Needed by | How to get it |
|---|---|---|
| `WHATSAPP_TOKEN` | staging agents (provisioning copies it into each staging tenant secret) | Meta Business Suite → system user with a permanent token for our test WABA |
| `WHATSAPP_PHONE_NUMBER_ID` | same | WhatsApp Manager → the test number's Phone number ID |

### `voice-platform/billing` (JSON) — added with SaaS billing (milestone 8)

| Key | Needed by | How to get it |
|---|---|---|
| `YOCO_SECRET_KEY` | API (charging businesses for plans and minutes) | Our own Yoco merchant account → developer keys (test key while building) |
| `YOCO_WEBHOOK_SECRET` | API (verifies Yoco payment webhooks) | Returned when registering the webhook with Yoco |

### Generated, nothing to do

| Secret | Notes |
|---|---|
| `voice-platform/db-master` | RDS master user and password, generated by CloudFormation |
| Tenant DB role passwords | Generated by provisioning, stored in each tenant secret |

### Not secrets

No keys at all for Bedrock, S3, SES, SNS, ECR or Cognito: the services use IAM roles, and the web app's Cognito
client is public. GitHub Actions uses OIDC; `AWS_DEPLOY_ROLE_ARN` is a repo variable, not a secret.

## Tenant secrets (written by provisioning, one per tenant environment)

`voice-platform/tenants/<slug>/<env>` (JSON, read by `tenant.yaml`; every key must exist, empty is fine):

| Key | Source |
|---|---|
| `DATABASE_URL` | Provisioning: the tenant's own DB role and password, schema `t_<slug>_<env>` |
| `WHATSAPP_TOKEN` | Staging: copied from `voice-platform/test-whatsapp`. Prod: the business's token from Embedded Signup (or entered by an admin until we're a Tech Provider) |
| `WHATSAPP_PHONE_NUMBER_ID` | Same as above |
| `YOCO_SECRET_KEY` | The business's own Yoco key, or empty for pay-at-venue only |

## Development machine only

| Secret | Where |
|---|---|
| Modal token | `docker compose -f legacy/compose.yaml run --rm modal token new` stores it in the Modal CLI's config; needed to deploy the TTS |
| AWS credentials | `~/.aws` profile for running CloudFormation deploys |

## Legacy server (until Demo Co moves to the platform)

The live single-business server keeps its `.env` in SSM (`legacy/deploy-server.sh env`). It needs
`DEEPGRAM_API_KEY`, `CF_TUNNEL_TOKEN`, `DB_PASSWORD`, `DASHBOARD_DB_PASSWORD`, `METABASE_DB_PASSWORD`,
`TOOLS_SECRET`, the `WHATSAPP_*` keys, `OPENWA_*`, `VOXCPM_*` and optional fallbacks (`ANTHROPIC_API_KEY`,
`CLOUDFLARE_AI_TOKEN`). It goes away at cutover.
